The speculation cut escalated-clip latency ~20% but fired a wasted KO decode on ~5× more clips than consumed it; on a saturated GPU that waste came out of everyone's queue (−30% throughput). The gather only runs where both calls are always consumed — Hangul clips got ~340 ms faster for free. Lesson, recorded in the code: speculative work cannot buy tail latency on a saturated shared GPU.

05 · SERVING ARCHITECTUREMicro-batcher vs vLLM continuous batching

The decode engine itself, same model (Qwen3-ASR-1.7B), bare requests. The production design (offline engine + lock + 10 ms coalesce queue) plateaus near 31 req/s no matter the GPU, batch cap (8→32) or VRAM (0.55→0.85): each locked generate() returns only when its slowest clip finishes, and nothing joins mid-flight. vLLM serve kept scaling to c64 without saturating the 5090.

06 · ANCHOR ON THE 5090The shim works; the tunnel dominates

The full anchor pipeline ran on the rented box with decodes shimmed onto vLLM serve (context via system message, language forcing via assistant-prefill with a custom chat template, logprobs → confidence). Functionally correct — every tier, transcript and gate matched. But the guard still lives on gpu-225, so each request shipped audio through an SSH tunnel via the Mac (~1.3 s round trip), which set the floor for every configuration equally.

07 · FINDINGSWhat today established

  1. The anchor guard costs ~2× plain decode (629 vs 339 ms mean) — the price of the fabrication checks, dominated by the ~20% of clips that escalate through the serial KO/guard/Xeus chain.
  2. Long clips poison the tail. Keeping the benchmark to <5 s clips (84% of traffic) removed the entire 5–6 s p95 band. If production mixes long clips, isolate them in a separate worker pool.
  3. Network is negligible on LAN — ~28 ms fixed; all congestion effects are server-side queueing.
  4. Speculative decoding hurt under load (−30% throughput) and was reverted; the zero-waste guard overlap was kept (Hangul clips −43% latency). Deployed on gpu-225.
  5. The serving design is worth more than the GPU. Micro-batcher: ~31 req/s ceiling on a 5090. vLLM continuous batching: 242–467 req/s on the same card, 58 on the 3090 Ti. A GPU upgrade without the serving swap buys ~nothing at production concurrency.
  6. Anchor logic ports cleanly onto vLLM serve via a ~50-line flag-gated shim — same tiers, same outputs. Next step for a real end-to-end number: co-locate the guard (and batch it), then re-run c4/8/16.

Bottom line: current production traffic (≈0.02 req/s average) is comfortably served by today's stack. The moment scale or batch backfills matter, the path is: vLLM serve for decode, guard co-located and micro-batched, anchor logic unchanged behind the shim.
